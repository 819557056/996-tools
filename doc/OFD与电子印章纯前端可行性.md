# OFD 与电子印章纯前端可行性

更新日期：2026-10-23。**技术上可以在浏览器实现，但当前未迁移。按本轮决定，已移除 OFD 签章验签、OFD 签章诊断、电子印章制作三个功能及 Java 接入，不在本轮重写。** 全站保留 36 个工具，运行不依赖 Java；PDF 本地验签、8 个 PKI 工具及离线 OCSP/CRL 继续提供。

## 能力与难点

| 能力 | 纯前端可行性 | 需要完成的工作 |
| --- | --- | --- |
| 印章图片 | 高，适合独立实现 | 用 Canvas/SVG 绘制圆形、椭圆、方形、文字与图形，导出 PNG/SVG；控制中文字体、弧形排版、尺寸和清晰度。图片本身不包含电子签名或可信身份 |
| SES 电子印章制作、解析及验证 | 可行，复杂度中高 | 按目标规范与版本构造 ASN.1/DER、生成制章签名，处理 SM2/SM3、证书、印章有效期及授权签章者；明确制章者与签章者授权关系、证书链与用户提供信任锚的验证边界。已有密码组件可复用，不能只把 PNG 包装为 DER |
| OFD 验签与诊断 | 可行，复杂度高 | 安全解析 ZIP/XML、文档与签名路径，按具体规范确定原始引用字节、XML 规范化规则和摘要范围，检查引用文件摘要、SES 签名及签名覆盖内容；拒绝路径穿越、重复条目、解压膨胀和不支持结构 |
| OFD 签章、预览及定位 | 可行，复杂度高 | 除验签能力外，还需正确写入签名目录和清单、StampAnnot、引用摘要与签章值；处理 mm 坐标、页框、坐标变换、多页/骑缝、字体/字形/路径和页面渲染。签名有效与可视位置正确需要分别验证 |

浏览器已有 ZIP、XML、ASN.1、Canvas/SVG 和密码库可作为基础；CPU 密集处理可放入 Worker。SM2 通常由 JavaScript 或经验证的 WebAssembly 实现，不能假设所有浏览器原生 WebCrypto 都支持。文件和密钥可保持在本地，但这不会自动建立外部信任或解决签章格式兼容问题。

## 后续若重建的验收条件

先明确支持的 OFD/SES 规范版本、算法、签名封装和预览范围，再依次实现图片、SES、OFD 验签、OFD 签章与完整预览。复用现有 PKI、SM2、格式转换及 Worker 能力；本轮未承诺这项后续开发或交付时间。

必须使用独立实现和真实厂商样本双向互通：前端签发由独立工具验签、独立工具签发由前端验证，并检查图片字节、授权关系、签名目录、引用摘要、篡改拒绝、多签名、字体和坐标。不以同一实现的“自己签、自己验”代替互操作验收。数学签名、文件完整性、印章授权、证书信任、吊销及可信时间应分别报告，未检查项明确显示。

历史 B 方案及 Java 验收保留于[集成运行与验收](EsealTool集成运行与验收.md)与[功能对比与可行性](EsealTool功能对比与集成技术可行性.md)，仅供追溯，不是当前部署要求。当前 PDF 验签和离线吊销的边界见[实施记录](PDF验签前端迁移评估.md)。
