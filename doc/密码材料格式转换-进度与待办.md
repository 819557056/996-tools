# 密码材料格式转换：进度与验收

更新日期：2026-10-23。状态：**已完成格式转换并扩展至纯前端 PDF 验签和离线 OCSP/CRL 材料。** 本记录替代此前“暂停、10/11 通过、C1 未修复”的状态。OFD 签章验签、OFD 签章诊断、电子印章制作及 Java 服务接入现已移除；当前保留 36 个工具，零 Java 运行依赖。

## 1. 已完成需求

- 密钥、证书、签名值、密文、数字信封等共用 EncodedOutput：Hex / Base64；有头 / 无头；Hex 大小写；不换行或每行 32 / 64 / 76 字符；LF / CRLF。
- 复制和文本下载使用同一格式化结果；本地材料另提供真实二进制文件下载。展示转换保持原始字节不变，Base64 不编码 Hex 字符串。
- SM2 裸密钥可转换为真实 SPKI / PKCS#8 DER，再包装标准 PEM；裸签名、密文、信封及 SM4 材料使用自定义头，并说明其不是标准密钥 PEM。
- 既有页面已接入 SM2 加解密、签验、综合工具、SM4、数字信封、证书查看器。解密/验签/解信封输入支持 Hex、Base64、带头尾文本；纯 Hex 字符的自动识别优先按 Hex，歧义输入可手选编码。
- 常用 PKI 的 8 个纯前端入口生成的密钥、CSR、证书、PFX、密文和证书数字信封复用同一输出转换组件，并支持原始二进制下载；见[本地 PKI 工具使用与验收](本地PKI工具使用与验收.md)。原 Java 结果面板及 OFD/印章工具已删除，独立 JKS/KeyStore 管理也不再提供。
- 本地 PKI 现支持加密 PKCS#8、SEC1 及混合 Base64/Hex/DER 证书文件导入；每份材料独立规范化后再组合，SEC1 保留 `EC PRIVATE KEY` 头。CSR 扩展、证书有效期和链验证结果提供可读字段，原始 JSON 可展开查看。
- PDF 本地验签支持证书提取与 JSON 报告下载；离线 OCSP 请求/测试响应接入同一 Hex/Base64、头尾及换行组件，采用 `OCSP REQUEST` / `OCSP RESPONSE` 头并提供 DER 下载，CRL 输入支持 `X509 CRL`。显示编码变更不改变签名内容。

## 2. 已修复的问题

### SM2 ASN.1 密文 C1 前缀

sm-crypto 裸密文使用 X(32)|Y(32)，ASN.1 适配器契约使用 04|X|Y。现已在加密调用边界明确补 04，在解密边界明确去除 04。不根据坐标首字节猜测格式。C1C3C2、C1C2C3、Hex/DER 与带头尾 Base64 往返均通过，并与 Java 双向加解密互通。

### P7 字节语义及证书提取

修正 SM3 原文字节、SM2 ZA/userId、签名属性 DER 排序，按 issuer/serial 匹配证书并提取 SM2 公钥；拒绝不匹配材料、不支持算法和多签名者。修复 Node Buffer/TypedArray 子视图边界，以及空原文 attached 被错误编码为 detached 的问题。P7 验签失败不再静默尝试裸签名。旧错误摘要语义不作为标准兼容模式保留。

## 4. 保留边界

- 浏览器 P7 是单签名者 SM2/SM3 工具，数学验签通过不代表证书链信任、吊销或可信签署时间有效。
- PDF 本地验签有独立的多签名者 CMS 支持边界，不能把 P7 页的限制套用到 PDF 页。PDF 不检查吊销证据或 TSA 信任；离线 OCSP/CRL 工具不查询在线状态，生成的响应仅是用户指定状态的测试材料。
- 签名/密文结构转换与显示编码是两个层次；自动编码识别不能代替用户确认算法及材料结构。
- PDF 第三方样本兼容与静态部署验证仍应按发布范围进行；正式 CA/HSM、OFD 和电子印章不属于当前功能。已移除功能的前端重建可行性见[独立评估](OFD与电子印章纯前端可行性.md)，本轮仅移除、不重写。
